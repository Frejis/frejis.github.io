Signed Delivery

A signature does not just prove a message wasn't changed - it proves who could have made it. This page signs a real message with a real key, then breaks that guarantee three different ways so you can see exactly what each one relies on.

When your computer downloads a software update, it has to answer two questions before installing it: did this really come from the vendor, and did anyone change it on the way? A digital signature answers both at once. Without one, anyone who can sit between you and the download can hand you their own file instead, and nothing on your machine would notice.

Part 2 · the trust chain

  

    One valid signature only proves a document came from whoever holds that
    key. Trusting a website or a piece of software needs a
    chain: a root you already trust vouches for an intermediate, which
    vouches for the thing you actually received. Attack any one link and
    watch the chain break exactly there - the rest keeps working.
  

  

    This is the machinery behind the padlock in a browser's address bar. The
    browser does not know your bank; it knows a short list of organisations
    it was shipped trusting, and follows the vouching backwards until it
    reaches one of them.
  


  

    

    

      

      

        
        
        
        
      

    

  

  

    Note what does not happen: breaking one link leaves the others' own
    signatures perfectly valid. Each certificate only ever promises
    something about the key directly below it, so the failure stays where
    it happened instead of spreading, and a browser can tell you precisely
    which link it could not trust.
