A4 · property-based testing

The part of a fuzzer nobody shows you

Feed a function thousands of random inputs and one of them breaks it. That counterexample is usually huge and unreadable. A property-based tester's real trick is shrinking: automatically simplifying the failure until nothing more can be removed without the bug disappearing. This page is a miniature QuickCheck built from scratch, and it shows you that process happening.

Watching it shrink

Every row below is a candidate the shrinker actually tried. Red still fails the property, so the shrinker keeps that candidate and tries to simplify further. Green means the candidate now passes, a dead end - the shrinker backs up and tries something else. The chart is the size of the accepted candidate at each step: a descending staircase.

How many runs it typically takes to find a bug

Runs the current subject from scratch across many different seeds (no shrinking, just looking for the first failure) and histograms how many random inputs it took each time. A wide spread, or a long tail, is a sign the bug is easy to miss with too small a run budget.
