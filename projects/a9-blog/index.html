Ten things I built to be poked at

Cryptography and programming-language work is hard to show on a CV: the interesting part is a protocol or an algorithm, and both are invisible. So each of these ten demos takes one such mechanism and puts it on screen where you can step through it, break it, and watch it react. Everything runs in your browser. No build step, no dependencies, no server, no network calls.

How to run any of this

There is nothing to install. Clone the repository and double-click any project's index.html, or serve the repository root with whatever static server is nearest to hand: 

python -m http.server 4180
npx serve .

Then open projects/a9-blog/index.html and work from there. The logic in each project lives in DOM-free modules, so the tests run under Node's built-in runner with no test framework: 

node --test "projects/<slug>/*.test.js"

Use the quoted-glob form. Passing a bare directory to --test is rejected by Node 24 on Windows.

About these projects

These are demonstrations, not products. Each one exists because some piece of machinery is normally invisible — a protocol transcript, a unification trace, a worklist converging, a privacy budget being spent — and the fastest way to show I understand it is to let you watch it run and interfere with it.

That means they are deliberately small, and honest about it. Every README ends with a "What this is not" section listing what a real system would need and this one does not have: no threshold decryption in the ballot box, no polynomial commitment in the sumcheck, no alias analysis in the taint tracker. Overselling a demo is the fastest way to make a reviewer distrust everything else in it.

The zero-dependency rule is on purpose. Nothing here can rot because a package was unpublished or a bundler changed its config format, and a reviewer can read the source straight out of the folder without a toolchain. The demos should still open in five years.
