A15 · time-series store & streaming telemetry

A time-series database for streaming network telemetry

This page streams generated telemetry through a real Gorilla-style compressor, an append-only store with label queries and downsampling, and a rate calculation that survives a device reboot — and reports what it actually measured, live.

A fibre network has millions of ports, and each one reports rx/tx counters, optical light level and CRC errors every few seconds, forever. Stored plainly that is 16 bytes a reading, and keeping all of it costs real money, so this store keeps the difference between one reading and the next instead of the readings themselves — and since the readings barely change, the difference is usually almost nothing. The telemetry here is generated by this page, not captured from real hardware; the compression measurement over it is real.

Fault injection — watch the detector and the rate calculation react

Network equipment counts bytes since it last started up, and that count goes back to zero when the device reboots. Work out the speed by simply subtracting the previous reading ((v[i] - v[i-1]) / dt) and the moment of the reboot reports a huge negative throughput — nonsense a network engineer will recognise instantly. This page computes both, side by side, so the bug and the fix are both visible.

A monitoring system that reports minus forty gigabits every time a switch reboots trains its operators to ignore it, which is how the real fault goes unnoticed.

Query panel — it is a database, not an array

Series are identified by a metric name plus labels, e.g. rx_bytes{node="aar-olt-01", port="1/1/2"}. Enter a matcher below — exact match, a wildcard fragment, or a negative match — and see which series it selects.

Compressing the data is only useful if you can still ask questions of it afterwards — "every port on this device" has to stay one query, not a scan of everything ever stored.
