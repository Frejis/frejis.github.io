A15 · time-series store & streaming telemetry

A time-series database for streaming network telemetry

A fibre access network reports rx/tx counters, optical light level and CRC errors from every port, once every few seconds, forever. Stored naively that is 16 bytes a sample. This page streams generated telemetry through a real Gorilla-style compressor, an append-only store with label queries and downsampling, and a rate calculation that survives a device reboot — and reports what it actually measured, live.

The headline: bytes stored versus bytes a naive format would use

A naive format spends 8 bytes on the timestamp and 8 on the value — 16 bytes a sample, whether you send it as a packed binary record or (worse) JSON. Gorilla (Pelkonen et al., Facebook, VLDB 2015 — the scheme behind Prometheus's and InfluxDB's storage engines) stores the delta-of-delta of timestamps and the XOR of consecutive values instead, both in a variable-length bit code. Press "stream telemetry" below to generate a simulated network and measure the real result, not the paper's.

Fault injection — watch the detector and the rate calculation react

Real interface counters wrap or reset when a device reboots. A naive (v[i] - v[i-1]) / dt across that transition produces a huge negative rate — nonsense a network engineer will recognise instantly. This page computes both, side by side, so the bug and the fix are both visible.
